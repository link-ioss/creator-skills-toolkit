# 从想法到视频

## 1. 每条视频使用独立文件夹

把工具仓库当成安装与教程入口；实际视频在别的目录制作，避免误提交私人素材。

```text
my-product-video/
  assets/          图片、录屏、音频等素材
  video-spec.md    已确认的视频需求与逐镜头安排
  render/          后续初始化的 HyperFrames 项目
```

HyperFrames 的初始化可能要求目标目录为空。如果需求和素材已经存在，可在新的 `render/` 目录初始化，由助手按工作流复制所需素材并记录路径；不要为了初始化删除已有文件。

## 2. 用 video-spec-builder 明确需求

提供发布平台、受众、时长、比例、要传达的一句话和已有素材。明确“先输出需求，不开始渲染”，避免两个视频技能同时抢接工作。

检查生成的 `video-spec.md`：镜头时长是否匹配总时长？文案是否准确？素材是否真实存在？旁白、字幕、音乐是否有明确安排？不能把未确认的假设当成确定事实。

## 3. 交给 HyperFrames

让助手读取确认后的需求，按当前路由选择工作流。不要仅靠改文件名把 `video-spec.md` 冒充 `BRIEF.md`：两者结构与职责不同。

当前 HyperFrames 的文件约定可查看 [brief-format.md](../skills/hyperframes/references/brief-format.md)；初始化后，助手应把确认内容写入 `BRIEF.md`，把镜头安排转到工作流要求的分镜结构。它需要的领域技能与运行依赖由上游安装流程补全。

本工具箱没有实现自动格式转换器，也不包含离线渲染引擎。已有需求可以减少重复提问，但不足的字段仍需补齐。

## 4. 预览、修改、导出

先确认画面和节奏，再检查字幕、声音、素材边界、文字溢出与总时长。修改镜头时同步相邻镜头和音轨时间。最后让助手运行所选工作流要求的检查并导出视频，报告实际输出路径、分辨率和时长。

示例交付要求：

```text
请输出适合竖屏平台发布的 MP4，并保留可编辑项目。
导出前确认全部素材可读取、无占位文字、字幕不超出画面、音轨完整。
请报告实际导出结果；如果渲染失败，不要把预览页面称为成品视频。
```

## 5. 下次继续

打开同一个视频项目，让助手读取现有需求与分镜，再提出具体改动即可。技能会更新，旧项目应保留原有版本信息；升级按上游检查流程执行。
