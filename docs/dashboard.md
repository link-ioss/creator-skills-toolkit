# 创作神经网络看板 · Neural Creator Dashboard

帮助你把分散的作品、笔记、方法和选题整理成一张可以探索的创作网络。

首页由一颗发光球和五只代表不同模块的发光水母组成。点击水母，触须会以伞状展开，连接到具体内容；再点击一篇内容，右侧分析栏会展示相关数据、出链、反链、双向共振和二度关联。

看板来自 [luoluo-121/neural-creator-dashboard](https://github.com/luoluo-121/neural-creator-dashboard)，是 **React + Vite 纯前端项目**。默认本地运行，图谱分析使用本地规则，不调用 AI，也不自动从抖音、小红书等平台获取数据。下载项目、安装依赖需要联网；本地导入笔记不需要联网。不要把它描述为本工具箱作者原创的看板。

## 五个模块分别有什么用

| 模块 | 用途 | 可以放什么 |
|---|---|---|
| 作品库 Works | 回顾已发布内容及其表现 | 标题、发布日期、正文、观看量、收藏量、涨粉等 |
| 概念网络 Concepts | 围绕共同主题发现内容关联 | 多篇作品或方法笔记共同出现的话题标签 |
| 方法库 Methods | 积累可重复使用的创作方法 | 写作方法、脚本模板、拍摄流程、复盘笔记 |
| 选题池 Ideas | 保存和安排待创作的想法 | 选题、平台、优先级、状态、备注 |
| 创作台 Drafts | 继续写草稿并追溯选题来源 | 草稿正文、对应的来源选题 |

出链表示当前内容指向其他内容，反链表示其他内容指向当前内容；双向共振用于观察互相连接的内容，二度关联帮助你继续探索间接联系。这些关联由规则推导，不代表 AI 已阅读并判断了内容质量。

## 需要的环境

- Git：用于克隆上游项目；没有 Git 也可以下载 ZIP。
- Node.js：上游要求 20.19+ 的 20.x，或 22.12 及以上；新安装建议使用符合要求且仍受支持的 LTS 版本。
- npm：通常随 Node.js 一起提供。
- 浏览器和终端。

先在终端检查：

```bash
git --version
node -v
npm -v
```

本仓库的 `skills/neural-creator-dashboard/` 是给 AI 助手阅读的技能说明，不是完整网页程序。运行看板需要按下面步骤获取上游项目。**不要把运行依赖或个人数据装进技能目录。**

## 1. 获取项目模板

在你希望保存项目的位置打开终端，例如自己的项目文件夹，然后执行：

```bash
git clone --depth 1 https://github.com/luoluo-121/neural-creator-dashboard.git neural-dashboard
cd neural-dashboard
npm install
```

如果已有 `neural-dashboard` 文件夹，先确认是否为之前的项目；已有项目可以直接进入目录，避免重复克隆或覆盖。没有 Git 时，可在上游仓库选择 **Code → Download ZIP**，解压后进入包含 `package.json` 的目录，再运行 `npm install`。

后文所有 `npm run ...` 命令都在这个看板项目根目录执行。

## 2. 先用示例数据运行

```bash
npm run dev
```

保持终端运行，打开终端打印的网址，默认通常是 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。如果端口被占用，以终端实际显示的地址为准。

检查首页是否出现光球和五只水母，点击「作品库」展开内容，再点击一篇查看右侧分析栏。仓库自带的内容与指标全部是虚构示例，不代表你的真实账号表现。

### 下次怎么打开

电脑重启或服务停止后，在终端进入原项目目录，重新启动：

```bash
cd "/你的项目路径/neural-dashboard"
npm run dev
```

再访问终端输出的网址。浏览器书签只保存地址，不会自动启动服务。停止服务时，在运行它的终端按 `Ctrl+C`。

## 3. 导入自己的 Markdown / Obsidian 笔记

如果让 AI 助手协助操作，先告诉它允许读取的笔记目录，并明确同意读取后再导入。无需提供账号密码、平台 Cookie 或 API 密钥。

导入脚本**只读取源笔记，不修改源笔记、不联网**；但会在看板项目里写入生成的数据文件，并切换数据入口，因此不是“任何文件都不写”。建议在重新导入前备份自己手工修改过的看板数据。

### 3.1 先练习导入示例笔记

```bash
npm run import -- --vault examples/vault
```

这会把示例 Markdown 转成看板数据。确认流程正常后，再导入真实笔记。

### 3.2 导入真实笔记目录

```bash
npm run import -- --vault "/你的笔记文件夹" --account "你的账号名" --followers 1000
```

把路径、账号名和粉丝数替换为真实值。路径带空格时保留引号。`--account` 和 `--followers` 可省略；只导入笔记时可以这样运行：

```bash
npm run import -- --vault "/你的笔记文件夹"
```

### 3.3 文件夹如何分类

以下是容易自动识别的目录命名示例：

```text
我的笔记/
├── 作品 works/
│   └── 桌面收纳实验.md
├── 方法 methods/
│   └── 三段式脚本.md
├── 选题 ideas/
│   └── 周末拍摄计划.md
└── 草稿 drafts/
    └── 收纳视频初稿.md
```

| 类型 | 可自动识别的常见目录词 |
|---|---|
| 作品 | 作品、works、已发布、published |
| 方法 | 方法、methods、模板、templates、流程 |
| 选题 | 选题、ideas、灵感 |
| 草稿 | 草稿、创作台、drafts |

识别不准时，显式指定相对于笔记根目录的文件夹；同类参数可重复传入：

```bash
npm run import -- --vault "/你的笔记文件夹" \
  --works "已发布/短视频" \
  --works "已发布/图文" \
  --methods "知识库/创作方法" \
  --ideas "灵感收集" \
  --drafts "正在写"
```

当前导入器需要至少识别到一篇作品，否则会停止并报告“没有找到作品笔记”。未识别的 Markdown 默认不会导入；必要时用 `--all-as-notes` 将它们作为方法笔记处理，但这不能替代至少一篇作品的要求。

### 3.4 作品数据如何填写

数据写在 Markdown 顶部由两行 `---` 包围的 frontmatter 中，正文写在后面。每个指标选择一个中文或英文字段名即可，不要把 `观看/views` 当成一个字段名。

下面是一篇**虚构示例**，可以放到 `作品 works/桌面收纳实验.md`：

```markdown
---
标题: 桌面收纳实验
发布时间: "2026-10-01 18:30"
类型: 视频
观看: 1.2万
点赞: 320
评论: 18
收藏: 86
涨粉: 12
分享: 9
曝光: 2万
封面点击率: 12.4%
平均观看时长: 21s
tags: [收纳, 生活实验]
---

这次用一个前后对比展示桌面变化。
脚本采用 [[三段式脚本]]，下次可以继续拍摄抽屉整理。
```

| 中文字段 | 英文字段 | 含义 / 示例 |
|---|---|---|
| 标题 | title | 可省略；缺失时使用 Markdown 文件名 |
| 发布时间 | date | 建议使用 `2026-10-01 18:30`；缺失或无法解析时使用文件修改时间 |
| 观看 | views | 观看/阅读数量，如 `12000` 或 `1.2万` |
| 点赞 | likes | 点赞数量 |
| 评论 | comments | 评论数量 |
| 收藏 | saves | 收藏数量 |
| 涨粉 | follows | 该作品带来的粉丝增量，不是账号总粉丝数 |
| 分享 | shares | 分享次数 |
| 曝光 | impressions | 曝光次数 |
| 封面点击率 | ctr | 如 `12.4%`，当前解析器保存为百分数数值 `12.4` |
| 平均观看时长 | duration | 如 `21s` 或 `21秒`，按秒填写 |
| 类型 | media | `视频` / `video` 或 `图文` / `images` |
| 标签、话题 | tags | 推荐写为 `[收纳, 生活实验]` |

当前解析器只支持简单的 `key: value`、行内列表和 `- 项` 列表，不是完整的 YAML 解析器；避免复杂嵌套。部分缺失计数会变成 0，所以有真实数据时应明确填写，不能把显示的 0 一律理解为平台实际测得的 0。

### 3.5 双链与概念节点

- 用 `[[三段式脚本]]` 引用另一篇笔记，名称尽量与目标标题或文件名一致。
- 同一个话题标签至少出现在两条已导入的作品或方法笔记中，就可成为概念候选。
- 当前导入器按频次取最多 20 个概念；不是所有标签都会显示成概念节点。
- 只写链接、不导入对应目标时，可能出现未创建或无法匹配的目标。

当前默认最多导入最新 30 篇作品、40 篇方法笔记，正文最多保留前 6000 个字符。如果数量少于预期，可先检查这些限制：

```bash
npm run import -- --vault "/你的笔记文件夹" --max-works 100 --max-notes 100
```

更多参数可运行 `npm run import -- --help` 查看。

### 3.6 导入后发生什么

脚本会生成 `src/data/my-data.js`，并将 `src/data/index.js` 切换为读取它。开发服务器运行时通常会自动刷新；必要时刷新浏览器。修改源笔记后需要重新执行导入，不会自动持续同步整个 Obsidian 仓库。

恢复仓库自带的示例数据：

```bash
npm run import -- --reset
```

该命令切换数据入口，**不会删除已经生成的个人数据文件，也不会清空浏览器保存的草稿和选题**。

### 3.7 数据是表格怎么办

当前 Markdown 导入命令不直接解析 Excel 或 CSV。可以先转换成符合上面格式的 Markdown；也可以参考上游 `src/data/sample.js` 的结构，由助手生成 `src/data/my-data.js`，再把 `src/data/index.js` 改为：

```javascript
export * from './my-data.js';
```

需要保持 `snapshot`、`posts`、`postContent`、`notes`、`seedIdeas`、`seedDrafts` 和 `concepts` 等导出结构一致，作品标题与正文对应。完成后运行验证，不要仅改文件名就认为表格已经被导入。

## 4. 个性化设置

| 文件 | 可以修改什么 |
|---|---|
| `src/config.js` | 品牌名称、图谱中心名称、头像、页脚文字、浏览器存储前缀 |
| `src/neural/theme.js` | 场景主题相关设置与素材路径，具体以文件现有字段为准 |
| `src/neural/neural.css` | 顶部 CSS 变量中的颜色等视觉设置 |
| `public/` | 放置你自己的头像文件，再在配置中填写相对路径 |
| `public/media/` | 光球、水母等视频素材；保持原文件名，或同步修改代码中的引用路径 |

首页的光球和五只水母是核心动态效果。可以更换视频或颜色，但不要直接删除、隐藏或改成静态图片。相关动画还包含画布逐帧绘制逻辑，改动前阅读上游 `AGENTS.md`。

## 5. 验证与查看效果

```bash
npm run verify
npm run build
```

两条命令都应通过，再在浏览器里检查：

1. 首页光球和五只水母正常出现并运动。
2. 点击「作品库」水母，触须与内容节点展开。
3. 点击一篇内容，右侧出现分析栏与关联信息。
4. 作品库、选题池、创作台页面可以正常使用。
5. 浏览器开发者工具的 Console 没有报错。

`verify` 检查结构与核心动效代码，并不能代替实际观看动画；`build` 成功也不代表你填写的业务数据一定准确。

## 6. 部署（可选）

`npm run build` 会生成 `dist/`，可部署到兼容的静态托管服务。若部署在网站子路径下，需要按实际路径配置 Vite 的 `base`，重新构建并检查素材是否正常加载。

**个人数据可能被打包进构建文件。** `.gitignore` 只能帮助避免 Git 提交，不能阻止构建工具把导入的数据打包。未经明确同意，不要公开部署个人笔记、客户资料或真实账号明细。需要公开演示时，先切回虚构示例数据，再重新构建并检查产物。

## 数据保存与注意事项

- `src/data/my-data.js` 包含导入的个人笔记，上游已将其加入 `.gitignore`；不要随意提交或公开分享。
- 选题、草稿、目标等编辑状态保存在当前浏览器的 localStorage，换电脑、换浏览器或清空站点数据后不会自动恢复；重要内容应另行备份。
- 重新导入后仍看到旧的选题/草稿，可能是浏览器存储覆盖了新的初始数据。确认已备份需要的内容后，可修改 `src/config.js` 的 `storagePrefix` 使用新存储空间，或清理该站点的 localStorage。修改前缀不会搬迁旧草稿。
- 不要在这个默认本地看板里随意添加联网请求、统计脚本或 AI 调用。若要扩展成联网产品，应另行设计数据权限、密钥保存与同步服务。
- 导入源笔记不会把你的内容许可变成 MIT 或非商业许可；用户内容仍属于其权利人。
- 更多开发约定见实际看板项目根目录的 `AGENTS.md`。

## 常见问题

| 问题 | 先检查什么 |
|---|---|
| `npm: command not found` | 是否安装 Node.js/npm，重新打开终端后版本命令是否可用 |
| 找不到 `package.json` | 终端是否位于克隆或解压后的看板项目根目录 |
| 网址打不开 | `npm run dev` 是否仍在运行；是否使用了终端实际打印的端口 |
| 页面仍是虚构数据 | 导入命令是否成功；数据入口是否切换；是否打开了另一个项目的页面 |
| 导入时提示没有作品 | 作品目录名是否可识别，或是否需要 `--works` 指定目录 |
| 笔记少于预期 | 是否被目录规则排除；是否达到默认作品/方法数量限制 |
| 没有概念节点 | 是否有相同标签出现在至少两条已导入的作品或方法笔记中 |
| 更新笔记后看板没变化 | 是否重新运行导入；旧选题和草稿是否来自 localStorage |
| 光球或水母不显示 | 视频素材路径、浏览器 Console 和 `npm run verify` 是否正常 |

## 与视频制作怎么搭配

先在看板中积累选题与方法，再到独立视频项目使用 `video-spec-builder` 形成需求和分镜，交给 `hyperframes` 制作。完成后，把作品链接和真实指标写回自己的笔记，再重新导入看板。

这是一套可以串联的工作方式，当前没有自动跨工具同步，也没有抖音/小红书抓取服务或 AI 问答后端。视频步骤见 [视频制作教程](video-workflow.md)。
